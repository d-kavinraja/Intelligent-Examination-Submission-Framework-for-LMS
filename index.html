The Challenge

Why IESF-LMS Exists

Academic institutions transitioning to digital grading face major logistical hurdles with physical answer scripts.

The Problems

Manual Labor

Individually scanning, renaming, and uploading hundreds of answer scripts is time-consuming and inefficient.

Human Error

Manual processes are prone to uploading wrong files or mislabeling student submissions.

Security & Integrity

Unverified uploads can compromise the chain of custody for examination papers.

No Verification

Students lack a mechanism to verify their paper was scanned correctly before grading.

The Solution
1

Bulk Ingestion

Staff uploads scanned PDFs via drag & drop. AI extracts metadata automatically — no manual naming needed.

2

Intelligent Processing

YOLO detects text regions, CRNN reads register numbers and subject codes from each page with high accuracy.

3

Student-Led Submission

Students verify their papers via secure PDF viewer and submit to Moodle, ensuring non-repudiation.

Core Concept

An intelligent intermediary between the physical examination hall and the digital grading environment, ensuring secure validation and student verification at every step.

Non-repudiation Audit Trail Secure Tokens AI Extraction

Getting Started

Quick Setup

Get up and running locally in minutes.

Prerequisites

Python 3.10+ PostgreSQL 14+ Moodle LMS with Web Services Git
1
Clone Repository
git clone https://github.com/d-kavinraja/Intelligent-Examination-Submission-Framework-for-LMS.git
cd Intelligent-Examination-Submission-Framework-for-LMS/exam_middleware
2
Create Virtual Environment
python -m venv venv

# Windows
.\venv\Scripts\activate

# Linux / Mac
source venv/bin/activate
3
Install Dependencies
pip install -r requirements.txt
4
Configure Environment
copy .env.example .env
Edit .env with your PostgreSQL credentials, Moodle URL, and HF Space URL
5
Setup Database
psql -U postgres -c "CREATE DATABASE exam_middleware;"
python init_db.py
Creates tables, default admin user (admin/admin123), and initial mappings
6
Run Application
python run.py
Server starts at http://localhost:8000 — Staff Portal at /portal/staff, Student Portal at /portal/student

Technical Deep Dive

Execution Flow & Codebase Architecture

Complete analysis of the system's multi-stage pipeline from setup through deployment.

1

Setup & Initialization

Environment Configuration: PostgreSQL, Moodle LMS, Email services, ML inference, file storage

Database Initialization: Creates core tables (ExaminationArtifact, SubjectMapping, StaffUser, StudentSession, AuditLog)

Service Dependencies: FastAPI app with middleware stack, async connection pooling, OAuth2 setup

python init_db.py # Auto-creates tables + admin user (admin/admin123)
2

Data Pipeline — Ingestion (5 Stages)

  • Stage 1 — File Reception: Staff uploads via REST API with JWT authentication
  • Stage 2 — Filename Parsing: Regex extraction of register number (12 digits) & subject code
  • Stage 3 — File Storage: SHA-256 hashing, async file I/O, persistent DB storage (BYTEA)
  • Stage 4 — Artifact Creation: Idempotent operation with transaction IDs, workflow status = PENDING
  • Stage 5 — Background Processing: Email notifications, audit logging

File Organization: uploads/pending, uploads/processed, uploads/failed, uploads/temp

3

Core Logic & Business Rules

Artifact State Machine: PENDING → VALIDATED → READY_FOR_REVIEW → SUBMITTED_TO_LMS → COMPLETED

Multi-Attempt Support: Max 2 attempts per exam type (CIA1, CIA2), admin-controlled unlock

Subject Mapping: Bidirectional lookup: subject code → assignment ID → course ID

File Persistence: Primary: filesystem | Fallback: PostgreSQL BYTEA (cloud resilience)

4

ML Pipeline — YOLO + CRNN

YOLO Component: YOLOv8 object detection for text region localization on answer sheets

CRNN Architecture: 6-layer CNN → 2-layer LSTM (512→256, bidirectional) → FC(512→classes)

  • Register Number: best_crnn_model(git).pth — 12-digit numeric prediction
  • Subject Code: best_subject_model_final.pth — 2–10 char alphanumeric

Confidence Scoring: Register ≥60%, Subject ≥70%

5

Student Portal — Verification & Submission

Authentication: Moodle token exchange → session creation → register number extraction

Dashboard: Grouped artifacts by exam type, real-time submission status

3-Phase Submission Workflow:

  1. Draft upload to Moodle (core_files_upload)
  2. Assignment association (mod_assign_save_submission)
  3. Submission finalization + admin lock (mod_assign_submit_for_grading)

Error Handling: Transactional approach with idempotent retry logic via transaction IDs

6

Deployment & Production

Render.com Cloud: Auto-scaling, PostgreSQL managed hosting, environment variable config

Async Architecture: FastAPI + asyncpg for non-blocking database ops, aiofiles for file I/O

Security Hardening: CORS middleware, GZip compression, JWT tokens, Fernet encryption, rate limiting

Database Backups: Daily snapshots, manual export/restore scripts included

ML Inference: Offloaded to HuggingFace Spaces (lightweight Render deployment)
